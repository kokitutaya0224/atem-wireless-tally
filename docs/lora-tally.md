# ATEM LoRa タリーシステム（E220-900T22S(JP)-EV2）

WiFi の届かない場所でもタリーを飛ばすための LoRa 版です。
**ベース局（送信機）1台 + タリー受信機 N台** の構成で、ベース局だけが WiFi/ATEM に接続し、
全カメラのタリー状態を LoRa でブロードキャストします。受信機は WiFi 不要です。

```
ATEM ──LAN──> WiFiルーター ~~WiFi~~> [ベース局: ESP8266 + E220] ~~920MHz LoRa~~> [受信機: ESP8266 + E220 + RGB LED]
                                                                              ~~> [受信機 ...最大20台分の情報を1パケットで]
```

## 使用モジュール

| 品名 | 役割 |
|---|---|
| E220-900T22S(JP)-EV2 ×2 | LoRa モジュール（LLCC68 / 920MHz / ARIB STD-T108 / 技適取得済み） |
| TX915-JK-11 | アンテナ（SMA。**アンテナなしで送信しないこと** — モジュール破損の恐れ） |
| NodeMCU (ESP8266) ×2 | マイコン |

## 配線（ベース局・受信機とも共通）

E220-EV2 のピンヘッダと NodeMCU を以下のように接続します。
**電源は必ず 3.3V**（E220 の UART 信号レベルは電源電圧に追従するため、5V 給電すると ESP8266 の入力耐圧を超えます）。

| E220-EV2 ピン | NodeMCU ピン | 説明 |
|---|---|---|
| VCC | 3V3 | 3.3V 給電（送信時ピーク電流に備え配線は短く太く） |
| GND | GND | 共通グラウンド |
| M0 | D3 (GPIO0) | モード切替。E220 内部弱プルアップ → 起動時 HIGH で問題なし |
| M1 | D4 (GPIO2) | モード切替。同上 |
| RXD | D1 (GPIO5) | ESP8266 → E220（SoftwareSerial TX） |
| TXD | D2 (GPIO4) | E220 → ESP8266（SoftwareSerial RX） |
| AUX | （未接続） | 未使用。Floating で可（ファームは固定ディレイで代替） |

受信機の RGB LED（コモンアノード）は WiFi 版と同じ:

| LED | NodeMCU ピン |
|---|---|
| R | D5 (GPIO14) ※220Ω |
| アノード（長い足） | 3V3 |
| G | D6 (GPIO12) ※220Ω |
| B | D7 (GPIO13) ※220Ω |

設定リセットボタン（オプション）: **D0 (GPIO16) ⇔ 3V3**（押下=HIGH。従来の D1 は E220 RXD に使うため移動）。

## 無線設定（ファームウェアが起動時に自動書き込み）

両機とも同じ設定。mode 3（M0=H, M1=H, 9600bps 固定）で `0xC0` コマンドにより設定後、mode 0 に移行します。

| 項目 | 値 | 理由 |
|---|---|---|
| アドレス | 0x0000（共通） | 透過送信モード＝同一アドレス+同一CHで全受信機に届く |
| チャンネル | CH10（922.6MHz / BW125kHz） | **CH0〜14 は送信休止 50ms のみで運用可**（CH15以降は1時間360秒制限があり不可） |
| エアレート | SF7 / BW125kHz（5,469bps） | 距離と遅延のバランス。10バイトパケットの電波送信時間 ≒ 40ms |
| UART | 9600bps 8N1 | |
| 送信出力 | 13dBm（20mW） | 日本版の最大値 |
| 送信方式 | 透過（transparent） | 宛先ヘッダ不要のブロードキャスト |
| RSSIバイト付加 | ON | 受信機がシリアルモニタに電波強度を表示 |

レジスタ値: `REG0=0x68` `REG1=0x01` `REG2=0x0A` `REG3=0x80`

キャリアセンス（送信前 -80dBm/5ms 監視）と送信休止 50ms はモジュールが法規に従い自動で行います。

## LoRa パケットフォーマット（10バイト固定長）

500ms ごとのハートビート + タリー変化時に即時送信。

| バイト | 内容 |
|---|---|
| 0 | マジック `0xA7` |
| 1 | フラグ（bit0: ベース局が ATEM に接続中） |
| 2 | シーケンス番号（送信ごとに +1） |
| 3–5 | PGM ビットマップ（リトルエンディアン24bit、bit0=カメラ1 … bit19=カメラ20） |
| 6–8 | PVW ビットマップ（同上） |
| 9 | チェックサム（バイト0〜8 の XOR） |

受信側は RSSI 付加設定により、パケット直後に RSSI 1バイト（dBm = 値 − 256）を受け取ります。

## 受信機の LED 表示

| 表示 | 意味 |
|---|---|
| 赤 点灯 | PROGRAM (ON AIR) |
| 緑 点灯 | PREVIEW |
| 消灯 | 非選択 |
| 青 点滅 | ベース局は生きているが ATEM 未接続 |
| マゼンタ 点滅 | LoRa 電波ロスト（2.5秒以上パケットなし）— ベース局停止 or 圏外 |
| 白 点滅 | 設定ポータルモード |

## 受信機のカメラ番号設定

受信機は常時 AP `ATEM-Tally-RX` を出しています。スマホで接続し `http://192.168.4.1` を開くと
カメラ番号（1〜20）の選択と LED テストができます。設定は EEPROM に保存されます。

設定ページの Status には以下のいずれかが表示されます（ベース局の設定ページにも同様の LoRa ステータスがあります）:

| 表示 | 意味 |
|---|---|
| `LoRa: OK (RSSI ... dBm)` | 正常受信中 |
| `LoRa: NO SIGNAL` | 自局のE220は動作しているが、ベース局からのパケットを受信できていない（ベース局停止・圏外・チャンネル不一致等） |
| `LoRa: MODULE ERROR` | 自局のE220自体が応答していない（配線・電源・アンテナ未装着などハードウェア側の問題） |

LED Test ボタンは押すと3秒間その色を保持します（タリー状態の点滅描画に即座に上書きされないよう保護しています）。

## ビルドと書き込み

```bash
# ベース局（送信機）
pio run -e lora_base -t upload

# タリー受信機
pio run -e lora_tally -t upload

# 従来の WiFi 版タリー（そのまま残してあります）
pio run -e esp8266 -t upload
```

## ベース局の設定

WiFi 版と同じポータル（AP `ATEM-Tally-BASE` → `http://192.168.4.1`）で
WiFi SSID/パスワードと ATEM の IP を設定します。カメラ番号の選択はありません
（全20カメラ分を常にブロードキャストするため）。

ベース局の LED: 緑点灯 = ATEM 接続中・送信中 / 青点滅 = ATEM 未接続 / 白点滅 = 設定ポータル。
